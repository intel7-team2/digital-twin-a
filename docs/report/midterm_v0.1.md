## 1. 프로젝트 개요

### 1) 프로젝트 목표 및 기대 효과

배터리 조립·검사 설비 앞단의 셀 입고 → 검사 → NG 분리 → 전압 구간 분류 → 4셀 세트 공급을 Factory I/O로 만든 가상 전공정에서 PLC로 제어하고, 셀마다 기록을 남겨 SCADA로 감시한다.

- 공정 개발과 시스템 설계, I/O·Interface 활용 능력 향상
  - 구역별 스텝 방식 래더로 입고·검사·분류·공급 시퀀스 구현
  - 셀 ID·LOT·전압을 위치별로 추적
  - Factory I/O·PLC·SCADA 태그 연동과 후공정(2B) 인터록 설계
- 시운전과 피드백으로 공정 수정·보완 능력 향상
  - 비정상 상황 8건 재현·검증
- 셀 단위 데이터로 공정을 설명할 수 있는 트윈
  - 셀마다 검사값·판정·박스 구성을 DB에 남겨, 세트 편차·수율·장비 편향을 숫자로 확인

### 2) 프로젝트 선정 이유 (계획서 v0.18의 해결할 문제)

| 문제 | 해결 방법 |
|---|---|
| 들어온 순서대로 4개씩 묶으면 세트 안 셀 전압 편차가 큼 | 전압 구간(A·B·C)별로 모았다가 같은 구간 4개씩 공급 |
| 불량 셀이 조립 설비로 넘어갈 위험 | 셀마다 판정, NG는 격리 레인으로 배출 |
| 한 LOT에서 불량이 반복돼도 계속 공급됨 | LOT별 NG 누계 3건이면 그 LOT 공급 보류, 알람 |
| 셀·세트 이력이 공정 사이에서 끊김 | 셀 ID·세트 ID를 공용 DB에 기록하고 2B로 인계 |
| 조립 설비가 준비 안 됐는데 세트가 넘어감 | 준비·공급 요청·수신 확인 신호로 인터록 |

확인 기준 (계획서 v0.18, 잠정): 같은 셀 데이터로 순서대로 묶은 세트 대비 세트 안 전압 편차 50% 이상 감소, 100셀 분류 오류 0건, NG·보류 셀 공급 유출 0건, 공급 세트 셀 ID와 DB 일치 100%, 비정상 상황 8건 기대 동작 일치.

## 2. 시스템 구조 및 사양

### 1) 시스템 구조도

```
 Factory I/O ──Modbus TCP── 브리지 (Python) ──MX Component── GX Simulator2 (래더)
                               │  PLC에 쓰는 프로그램은 브리지 하나
             2A HMI ───────────┤  (운전·정지·기준값·알람 확인은 PLC 쪽, DB를 거치지 않음)
                               │
                      수집기 (PLC 이벤트 메일박스 읽기, 로컬 저장 후 전송)
                               │ HTTPS · API 키
                               ▼
              battery-db API (FastAPI) ──▶ PostgreSQL 16  (Oracle Cloud VM)
                                                  ▲
                         Grafana SCADA ───────────┘ (읽기 전용, SSH 터널)
                         팩 라인(2B) 수집기·조회도 같은 DB
```

- 지금 시연은 브리지 대신 `plc/softplc.py`(시연용 소프트 PLC)가 Factory I/O와 Modbus로 연결된다. GX Works2 래더·GX Simulator2 연결은 아직 아니다 (interface.md).
- 공용 DB·API는 2A와 팩 라인이 같이 쓴다. 쓰기는 API, Grafana는 SQL 직결 (battery-db architecture-proposal.md, 팀 합의 전 제안).

### 3) 세부사양

#### PLC 디바이스 배정 (interface.md, 11/18 1차 협의)

| 범위 | 용도 | 쓰는 쪽 |
|---|---|---|
| M2000~M2099 | Factory I/O 센서 | 브리지 |
| M2100~M2199 | Factory I/O 액추에이터 | PLC |
| M2200~M2299 | PLC ↔ Python 신호 | PLC / 브리지 |
| D2100~D2199 | 측정값 (셀 ID, LOT, OCV, V1, I1, V2, I2) | 브리지 (값 생성기) |
| D2200~D2299 | 판정 기준값 (OCV 3500~3800 mV, 내부저항 60 mΩ 이하 등, 가정값) | 브리지 (SCADA에서 변경) |
| D2300~D2399 | 판정 결과 (등급, 사유, 내부저항) | PLC |
| D2700~D2799 | 이벤트 메일박스 (제안, 협의 전) | PLC |

- 로봇 프로젝트 0~1999, 2A 2000~2999, 2B 3000~3999로 대역을 나눔.
- 내부저항은 IEC 61960-3 직류 내부저항 방식으로 PLC가 계산: R = (V1 − V2) × 1000 / (I2 − I1).

| 항목 | 내용 |

| 백업 | 6시간마다 pg_dump, VM 14일·관리자 PC 60일 보관. 11/26 복원 시험 통과 |
| 유휴 회수 대응 | 매시간 약 6분 낮은 우선순위 CPU 사용 |

#### 데이터 수집 (수집기)

| 항목 | 내용 |
|---|---|
| 입력 | PLC 이벤트 메일박스 D2700~D2799 (헤더 4워드 + 레코드 8개 × 12워드), 100 ms 폴링 |
| 저장 | 로컬 SQLite에 먼저 저장한 뒤 PLC에 ACK. 인터넷이 끊겨도 쌓였다가 복구 후 전송 |

### 3) 데이터 수집 · 공용 DB

- 수집점: 셀이 지날 때마다가 아니라 값이 생기는 곳·판정이 갈리는 곳·소속이 바뀌는 곳만 이벤트로 기록. 셀 하나 정상 경로 9건 안팎 (2a-data-design.md)
- DB 스키마: 공정 v2 반영 (`sim_run`으로 시연 회차 구분, 검사 1차·재검, 설비 상태 구간, 알람). 셀 ID 형식 `R<회차 4자리>-<PLC 번호 6자리>`
- API: 조회 엔드포인트, 회차 시작·종료, 이벤트 묶음 저장. 키별 사용 기록
- 수집기: 메일박스 배치를 설정 파일로 분리해, 합의되면 설정만 바꾸도록 함

| 시험 | 결과 |

| 같은 이벤트 1,178건 재전송 | 새로 들어간 행 0 (중복 제거) |

| 이벤트 3건 삭제 후 재전송(replay) | 빠진 구간 감지 → 3건 복구 |
| 자동 시험 | 수집기 34개, API 41개 통과 |
| 백업 복원 | 11/26 00:00 백업을 빈 DB에 복원, 테이블 22개 행 수 일치 |
