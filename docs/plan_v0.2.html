배터리 셀 입고검사 · 매칭 공급 라인 디지털 트윈

실물 C 라인(18650 4셀 팩 검사 · 조립) 앞에 붙는 가상 전공정. 셀을 검사하고 LOT를 추적해서, 특성이 비슷한 4개를 한 세트로 묶어 C에 공급함.

  • 팀A팀 · 5명
  • 기간11/17 ~ 12/8 · 수업일 12일
  • 툴Factory I/O · MELSEC Q · OPC 서버
  • 상태초안 · 팀 합의 전

팀 회의에서 범위가 확정되기 전에 "현재 안"으로 쓴 초안. 목표 수치, 디바이스 번호, 부품 이름은 전부 잠정값이라 맨 아래 "정해야 할 것"을 먼저 보고 고치기.

1개요

왜 하는지

C 라인은 셀이 들어온 순서대로 슬롯 A~D에 넣음. 1차 검사는 전압만 보고 과방전 셀을 걸러낼 뿐이라, 전압이나 내부저항이 서로 다른 셀이 한 팩에 섞임. 직렬 팩은 셀 편차가 크면 약한 셀이 먼저 한계에 닿아서 팩 전체 용량과 수명이 줄어듦.

실제 팩 공장은 조립 전에 셀을 검사하고 특성이 비슷한 것끼리 묶어서 넣음. 그런데 C는 스테이션 하나짜리 축소판이라 이 구간을 실물로 붙일 자리도 설비도 없음.

C 앞단에 없는 "셀 입고검사 → LOT 추적 → NG 분리 → 특성별 분류 → 4셀 매칭 공급"을 Factory I/O에 만들고, 실제 PLC로 제어해서 C와 한 라인으로 묶기.

뭘 만드는지

  • 가상 전공정 라인. Factory I/O에 컨베이어, 센서, 푸셔, 버퍼 레인을 놓고 MELSEC Q 래더로 제어.
  • 셀 추적 로직. Factory I/O 부품은 데이터를 못 달고 다녀서, PLC 안에서 셀마다 ID · LOT · 전압 · 내부저항 · 등급을 들고 컨베이어 위치를 따라가게 함.
  • 매칭 공급과 LOT 보류. 같은 등급 4개가 모이면 한 세트로 C에 공급. 특정 LOT에서 NG가 반복되면 그 LOT만 공급을 막음.
  • 이력 화면. PLC 값을 DB에 쌓고 라인 현황, 셀 이력, 알람을 화면으로 봄.

역량 목표

  • 실제 PLC와 가상 설비를 OPC로 묶어서 하나의 제어기로 운전
  • 시프트 레지스터 기반 추적, 버퍼 관리, 세트 구성 같은 데이터 로직을 래더로 구현
  • PLC → DB → 화면으로 이어지는 수집 구조와 셀 단위 이력 관리
