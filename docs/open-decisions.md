## 결정할 것

| # | 무엇 | 지금 상태 | 제안 | 누가 |
|---|---|---|---|---|
| 1 | **A/B/C 경계값** | D2203 A ≥ 3750, D2204 B ≥ 3650 (가정값) | 이 값이면 시뮬에서 편차 감소 43%로 목표(50%) 미달. **실측 셀 분포에서 합격 셀이 1/3씩 나뉘게** 잡는다(시뮬 52%). 실측 전에는 3660/3700 임시 사용 | PLC + 검사 |
| 2 | **목표 문구** | "편차 50% 감소 (잠정)" | 셀이 원래 고르면(LOT 안 sd 20 mV) 50%는 구조적으로 못 넘는다(시뮬 25%). **"감소율 + 세트 편차 ○○ mV 이하"** 두 개로. ○○는 실측 sd 보고 정함 | 팀장 |
| 3 | **합격 기준 하나로 맞추기** | 래더·interface.md: 3500~3800 mV, IR ≤ 60 mΩ / SCADA 시뮬(`docs/scada/simulation/process.py`): 3.55~3.92 V, IR 14~32 | interface.md D2200~ 값을 기준으로 두고 SCADA 시뮬을 거기 맞춘다. 대시보드 숫자와 래더 판정이 다르면 발표 때 바로 걸림 | SCADA |
| 4 | **Reset과 LOT 보류 해제 분리** | 조작반 Reset(`M2017`)이 이상·진행 상태와 함께 LOT 보류(`M2500~`)·NG 횟수(`D2500~`)까지 지움 | Reset은 이상·진행 상태만. 보류 해제는 별도 신호(HMI에서 사유 입력 후). 설계 메모 "리셋으로 보류 이력을 지우지 않는다"와 맞춤 | PLC |
| 5 | **2A↔2B 인계 신호** | 래더에 없음. 배출 40초 초과 이상 정지만 있음 | 최소 4개로 시작. 2A가 쓰는 건 2A 대역, 2B가 쓰는 건 2B 대역: 2A→2B `공급 요청` 비트 + `세트 ID` 워드, 2B→2A `준비` 비트 + `수신 확인` 비트. 셀 ID 4개는 PLC 신호 말고 DB로 넘김. 주소는 2B와 합의 | PLC + 2B |
| 6 | **v2에서 셀 ID 확인 방법** | 검사기 4대 병렬 + 재검 합류라 분류 직전 셀이 누구인지 FIFO만으로 확신 못 함 | Factory I/O RFID Reader가 에디션에서 되면 그걸로. 안 되면 검사기 출구 해제 순간 FIFO에 넣고 분류 앞 센서에서 맨 앞과 대조(불일치 알람) | Factory I/O |
| 7 | 잼 처리 | 블레이드 해제 후 8초 미출발이면 카운트만 하고 계속 운전(T30, D2460) | 이상 정지로 바꿈. 셀이 어디 있는지 모르는 채로 계속 돌면 재고가 틀어짐 | PLC |
| 8 | 센서 ON 고착 감시 | 없음 | 도착 센서가 셀 길이 ÷ 벨트 속도(약 0.6초)의 몇 배 이상 계속 ON이면 이상. 배수는 시험으로 | PLC |
| 9 | 수집기 메일박스·ACK | 합의 전이라 수집기 미구현 | [측정 핸드셰이크](interface.md)와 같은 방식(PLC 쓰기 → 준비 비트 → 수집기 읽기 → ACK 비트)으로 이벤트 1건씩. 주소만 정하면 소프트 PLC로 먼저 만들 수 있음 | PLC + SCADA |
| 10 | 타이머 T 대역 | T0~T42 그대로 (대역 협의 전) | M·D처럼 대역 정하거나, T는 팀 PLC가 따로라 안 겹치면 그대로 둔다고 확인만 | 전체 |
| 11 | 중간보고서 빈칸 | `docs/midterm-report` 브랜치. 사람별 담당 범위 `[확인 필요]` 2곳, 한글 레이아웃 미확인 | 각자 한 줄씩 담당 범위 알려 주기. 한글에서 열어 보고 깨진 곳 알려 주기 | 전원 |
