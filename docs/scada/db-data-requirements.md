# 공용 DB 담당자에게 요청할 SCADA 데이터

[공정 v2 문서](../2a-data-design.md#4-db-스키마--battery-db)는 팀 공용 `battery-db`와 PostgreSQL 16을 기록한다. 아래는 화면과 집계에 필요한 논리 항목이다. 실제 스키마명, 테이블·뷰·열 이름, 값 규칙, 테스트 접속 방법은 DB 담당자가 제공하는 정의에 맞춰 연결한다.

## 1차 연동 필수 항목

| 데이터 | 요청 항목 | 활용 |
| --- | --- | --- |
| 실행·투입·ID | 실행 ID, 투입 시각·순번, LOT, Cell ID, ID 판독 여부와 실패 코드, 미판독 건을 연결할 투입 추적 키 | 실행별 분모, ID 발급 성공·실패, 셀 추적, 순서 기반 비교 |
| Vision 외관 | Cell ID 또는 투입 추적 키, 이벤트 키·판정 시각, PASS/FAIL/미판정 구분, 결함 코드 | 외관 공정 수율과 외관 FAIL 원인 |
| OCV·IR 검사 시도 | 실행 ID, Cell ID, 검사 고유 키와 시도 번호, 검사 레인·스테이션, 시작·완료 시각, OCV와 IR 원값 및 단위·스케일, 시도 결과·실패 사유, 최종 결과 또는 최종 결과를 결정하는 규칙, 적용 기준 버전 | OCV/IR 분포, 검사 소요 시간, 1차와 재검 구분, 최종 수율 |
| 분류 | Cell ID, 분류 시각, A/B/C 특성군 또는 미분류 상태, 목표 레인과 실제 레인, 진입 확인·불일치 여부 | 실제 분류 수량과 오분류 추적 |
| Kit와 구성 셀 | 실행 ID, Kit/박스 ID와 매핑, 특성군, 슬롯별 Cell ID·적재 시각, 완료 상태·시각, 취소 또는 재작업 표현 | Kit당 동일 특성군 고유 셀 4개, 구성 추적, OCV/IR 편차 |
| 이벤트 공통 | 안정적인 이벤트 ID, 실행·셀·Kit 참조 키, 타입·스테이션, 발생·기록 시각, 동일 시각의 순서 및 중복 제거 규칙 | 누락, 지연, 재전송 대응과 시계열 정렬 |

## 후속 화면에 필요한 항목

| 데이터 | 요청 항목 |
| --- | --- |
| 설비와 통신 | 설비 ID 또는 스테이션, 상태 코드와 시작·종료 시각, 하트비트 또는 최종 수신 시각, 단절·복구 시각 |
| 알람과 버퍼 | 알람 ID·코드·심각도·관련 설비, 발생·확인·해제 시각, 버퍼 위치·수량·시각 |
| 인계 | Kit/박스 ID, 인계 요청 ID, 요청·수신 시각 및 결과. 팩 조회가 필요하면 팩 ID까지 연결할 수 있는 키. |

## 연결 전에 합의할 사항

1. 조회 가능한 스테이징 주소·포트·DB명, TLS 조건, 필요한 뷰 또는 테이블에 `SELECT`를 허용하는 읽기 전용 Grafana 계정과 별도 비밀 전달 경로를 요청한다.
2. 관계 키·유일성·카디널리티, 상태 열거값, NULL 의미, 저장 시간대, 수집 주기, 지연·정정 및 재처리 규칙을 문서로 받는다. 공정 문서의 G/NG와 화면의 PASS/FAIL 대응, OCV V 및 IR mΩ 변환, 그룹 판정 출처를 함께 확인한다.
3. 정상, 외관 FAIL, 검사 중, 재검 회복·최종 FAIL, 미분류, Kit 완료·불완전, 중복 이벤트가 포함된 익명 샘플과 기대 집계표를 받는다. 실제 쿼리는 실행·기간 필터, 셀↔검사 시도↔Kit 연결, 중복 제거, 시간대 경계를 확인한 후 반영한다.
