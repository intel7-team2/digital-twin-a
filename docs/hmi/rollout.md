# 단계별 확장·검증과 담당자 협의

이 문서의 시험 절차는 후속 단계의 인수 기준이다. 이번 작업에서 PLC·Factory I/O·DB에 연결하거나 쓰지 않는다.

## 단계와 완료 기준

| 단계 | 범위 | 다음 단계 진입 기준 |
| --- | --- | --- |
| 0. v0.2 설계 | 3개 화면, 논리 데이터·명령 계약, 주소 근거와 미확정 목록 | 담당자가 화면 범위 및 계약 초안을 검토. 현재 단계. |
| 1. 가짜 입력 화면 | 외부 연결 없는 로컬 스냅샷·이벤트·명령 응답 재생 | 동일한 화면에서 미수집/0/정상 대기/지연/단절/장애와 명령 상태를 재현. 항상 `가짜 입력` 표기. |
| 2. 읽기 PoC | 별도 승인 후 `line_v0` 로컬 읽기 JSON 어댑터. 씬과 포트 변경 없이 관측 | 씬 실행·일시정지와 `M2300` 운전 상태 분리. 링크 손실과 출구 센서 검증. 제어는 미연동 상태. |
| 3. v2 읽기 통합 | 합의된 브리지·스테이션 매핑으로 가상 씬과 태그 스냅샷 확인 | 네 검사기, IDC/RT, 레인 및 Kit의 실제 관측 근거별 정상·미수집을 확인. 태그·레이아웃 버전 고정. |
| 4. 가상 제어 시험 | 주소·권한·ACK 합의 뒤 격리된 가상 장비에서 브리지 단일 쓰기 경로 시험 | 명령 상관관계·타임아웃·중복·경합과 물리 조작 우선순위 확인. `RESET_FAULT`에서 보류/인계가 유지됨. 승인된 기능만 해당 프로필에서 사용 가능. |
| 5. 이력 및 실제 검증 | 별도 스테이징 공용 API·DB, 팩 라인 모의 응답과 이벤트 대조. 실물 연동은 별도 승인된 결선·안전 시험 뒤 시작. | API·DB 정지 중 조작 독립성, 로컬 저장 후 이벤트 재전송, 공급·인계 중복 방지 확인. 실제 실행 근거가 있는 경우에만 실물 프로필을 사용 가능으로 승격. |

## 기존 구성 변경 시 영향과 회귀 시험

| 변경 | 영향 범위 | 검증 항목 |
| --- | --- | --- |
| PLC 래더·장치 주소·스캔 | 주소 어댑터, 값 유효성, 명령 인터록·제어권 | 계약 버전, 부호/워드 순서, 펄스·ACK, B접점, STOP 우선, 사유 코드, 연결 단절 후 자동 재개 금지 |
| Factory I/O 씬·센서·레인 배치 | 시연 어댑터, 공정 지도, 스테이션 관측 기준 | 실제 감지로 셀 이동 확인. 병렬 합류·재검에 셀 ID 불일치가 없는지, 외관/최종 NG 경로, 4셀 배출 수량과 출구 감지 대조 |
| 브리지 프로토콜·발행 주기 | 통신·값 품질, 명령 타임아웃 추정, 화면서비스 | 연속 버전과 세션 재시작, 느린/누락 스냅샷, 이중 작성 방지, 발전적 상태 변경 시 호환 어댑터 |
| 공용 API·DB 스키마·라벨 | 이력 어댑터, 회차와 추적, Grafana 공통 조회 | `run_id`·검사 ID·`attempt`·Kit ID 연결, UTC/Asia/Seoul, API 중복 삽입 보호와 스키마 호환. 기존 조작 경로는 별도로 검사. |
| 기준·재검·LOT 정책 | 검사·설정 화면, 보류, 출하/인계 조작 가능 상태 | 검사 유효성 우선, 미측정·NG 분리, 동시 검사 기준 버전, 보류 중 미공급 Kit 차단, 별도 해제 감사 |

## 필수 시나리오

| ID | 입력·동작 | 화면·동작 합격 기준 |
| --- | --- | --- |
| HMI-01 | 회차 없음 → 회차 시작 후 투입 0건 → 셀 1개 | `미수집`과 확인된 `0`을 구분하고 이전 회차 집계가 섞이지 않는다. |
| HMI-02 | `IDLE` 보고 → 오랫동안 갱신 없음 → 연결 끊김 → 새 세션 | 대기와 지연·단절 및 마지막 시각을 분리하고, 세션 대사가 끝날 때까지 구 상태로 조작을 허용하지 않는다. |
| HMI-03 | 시작 연속 클릭, 권한 없음, 명령 송신 직후 ACK 손실 | 중복 물리 작동 없음. 권한·인터록 사유 표시. ACK 손실은 결과 미확정 후 조회·대사. |
| HMI-04 | START 대기 중 STOP, 이력 API 실패 상태의 STOP | 승인된 STOP 우선 정책에 따른 결과 확인. 이력 조회 실패는 검증된 정지 경로를 막지 않는다. 전달 불명 상태를 `정지 완료`로 표시하지 않는다. |
| HMI-05 | LOT 보류 중 RESET, 설정값 한 워드만 반영 | 장애 리셋 후 보류·인계 이력 유지. 부분 설정 반영 시 실패 또는 미확정 표시와 읽기 대사. 기존 PoC RESET과 직접 연결하지 않는다. |
| HMI-06 | VIS 미판독, 동일 시각 검사 두 건, 재검 대기·초과, IR 미측정 | ID·시도별 추적, 실패 코드·미측정 표현과 확정 NG 집계 분리. 실제 레인 진입은 확인 이벤트에서만 표시. |
| HMI-07 | 동일군 3셀/혼합 4셀 → 정상 4셀 → 응답 손실·재시작 | 불완전 Kit는 완료 표시 없음. 인계 재조회는 같은 요청 ID. 수량·수신 확인 대사 전 재배출/자동 재개 없음. |
| HMI-08 | 알람 확인 후 원인이 지속, 보류 해제 요청 거절 | 확인은 남고 활성 장애가 유지된다. 해제 거절 사유와 LOT 잠금 상태가 표시된다. |
| HMI-09 | API 저장 실패 후 동일 이벤트 ID 재전송, 로컬 저장 실패 | 성공 이벤트 한 건과 재전송 기록 대조. 로컬 저장도 실패하면 설계 메모의 공급 차단 규칙을 검증한다. |

## 담당자에게 확인할 미확정 항목

| 담당 | 확인할 결정과 필요한 근거 |
| --- | --- |
| PLC | START/STOP/RESET_FAULT·설정 저장·알람 확인의 수신 및 응답 주소, 명령 키·순번, STOP 우선순위, 현장 제어권, 모드, 리셋 범위, 현장 안전 회로 및 읽기 상태. 실제 스캔·하트비트·ACK/효과 확인 시간, T/C/X/Y와 M·D 대역 승인. |
| Factory I/O | v2 씬과 소프트/실물 PLC 선택, VIS1·VIS2·IDC 센서와 셀 식별 원천, RT 합류 안정성, 최종 NG 출구, 버퍼 센서 정의, 단절 시 출력 상태 및 4셀 배출 통합 근거. |

| 브리지·DB/API | 메일박스 주소 충돌과 ACK, 생산자/세션/순번 및 키 충돌 처리, 로컬 저장/재처리, 공용 API 채택·버전·권한, 이력 조회 스키마와 `fake` 회차 표시 규칙, 스테이징 시험 데이터. |
| 팩/2B·2A | 인계 상대 라인 식별, 요청·박스/Kit·셀 ID 형식과 시점, 기대/실제 수량, 출구와 수신 확인, 타임아웃·수량 불일치 조치, LOT 보류 통보·해제 권위 원천. |
| HMI·SCADA 운영 | 운전자·유지보수·조회 권한 분리, 단말·표시 환경, UI 갱신과 stale 기준, 기능별 사용 가능 근거, 기존 Grafana와 이력 링크 정책. |
