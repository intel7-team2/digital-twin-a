# HMI v0.2 화면과 와이어프레임

모든 와이어프레임은 배치 예시다. 데이터와 조작 표시 기준은 [인터페이스](interfaces.md)를 따른다. `—`는 값이 없는 자리이며 배포 화면에서는 이유를 함께 표시한다.

## 공통 영역

- 상단에 라인 `2A`, 데이터 환경 `설계 미리보기 / line_v0 모의 / v2 가상 검증 / 실물`, 현재 회차, 브리지·PLC 연결 상태와 마지막 정상 관측 시각을 표시한다. 이력 DB/API 상태는 별도 표시한다.
- 화면 전환 후에도 진행 중인 명령과 마지막 결과를 상단에 표시한다. 스테이션·Cell·Kit에서 해당 화면의 상세로 이동해도 회차를 유지한다. 과거 회차를 펼쳤을 때 라이브 조작을 숨기거나 비활성화한다.
- `준비`, `미연동`, `사용 가능`은 기능의 연동 상태다. 화면 예시와 문서만 존재하는 기능은 `준비 · 설계`로 표시하며 제어는 비활성화한다. `미연동`은 주소·연결·검증 중 빠진 이유를 표시한다. `사용 가능`은 해당 환경에서 검증된 기능에만 부여하며, 지금 조작할 수 있는지는 권한·품질·인터록·진행 명령을 별도로 평가한다.
- 상태는 색과 텍스트를 함께 사용한다. 미수집·미측정은 회색, 통신 단절은 연결 경고와 마지막 관측 시각, 운전 중·정상 대기는 서로 다른 상태 문구, 설비 이상은 스테이션·알람·심각도와 함께 표시한다. 빨간색만으로 단절과 설비 이상을 구분하지 않는다.

## 1. 메인 운전

```text
┌ Cellect 2A  [환경]  [회차]  브리지/PLC 상태  이력 상태  마지막 관측 ┐
│ 메인 운전 │ 검사·분류 │ 설정·알람                 진행 중 명령 —  │
├ 운전: —   정지 입력: —   비상정지 관측: —   운전 권한: —         ┤
│ [START]  [STOP]  [RESET]       조작 비활성: 브리지 명령 미연동     │
├ 공정 지도 ──────────────────────────────────────────────────────┤
│ IN → VIS1 → VIS2 → [T1 | T2 | T3 | T4] → IDC → SORT              │
│         외관 NG → RJ1             ↑        재검 대상 → RT ─┘     │
│       최종 배출 ← RJ2                  A/LA · B/LB · C/LC         │
│                                              ↓ BOX → OUT         │
├───────────────────────────────┬──────────────────────────────────┤
│ 회차 집계 · 출처               │ 인계 · 예외                     │
│ 투입 —  외관 NG —  재검 대기 — │ Kit —  요청 ID —  수신 확인 —    │
│ 완료 Kit —  열린 알람 —       │ LOT 보류 —   IDC 불일치 —        │
└───────────────────────────────┴──────────────────────────────────┘
```

- 공정 카드마다 설비 상태와 데이터 품질을 별도로 표시한다. 셀 이동이 추적되지 않으면 연결선은 공정 순서만 표시한다. `2A-RJ1/RJ2`는 경로와 배출 확인을 구분한다.
- `START`는 상위 제어권과 브리지의 최신 허용 상태를 확인한 뒤 요청한다. `STOP`은 시작 버튼과 충분히 떨어진 고정 위치에 두고, 향후 검증된 경로에서 간단히 요청할 수 있게 한다. `RESET`은 적용 대상과 사전 확인을 표시한다. 시작·리셋에 공통 Enter 단축키를 두지 않는다.
- 비상정지는 물리 장치 상태의 **관측 표시**다. PoC의 가상 상태는 `시뮬레이션`으로 표시한다. 브리지 경로가 사라지면 HMI 정지 전달을 확인할 수 없다는 상태와 현장 조작 위치를 함께 안내한다.
- 집계는 하나의 회차·정의에 한정한다. 확인된 투입 0건은 `0`으로 표시하고, 회차 없음이나 원천 미연동은 `미수집`으로 표시한다. Pack·2B 등 상대 라인 조작은 제공하지 않는다.

## 2. 검사·분류

```text
┌ 검사·분류   [선택 회차]   [Cell ID 검색]   라이브/이력 출처 ┐
│ VIS1 ID/LOT —     VIS2 외관 —      IDC ID 일치 여부 —       │
├ 검사기 ──────────────────────────────────────────────────┤
│ T1 [상태 — | Cell — | 시도 — | OCV — | IR — | 판정 —]      │
│ T2 [상태 — | Cell — | 시도 — | OCV — | IR — | 판정 —]      │
│ T3 [상태 — | Cell — | 시도 — | OCV — | IR — | 판정 —]      │
│ T4 [상태 — | Cell — | 시도 — | OCV — | IR — | 판정 —]      │
│ RT [상태 — | 대기 — | 시도 — | 사유 — | 최종 판정 —]       │
├ 분류·레인 ────────────────────────────────────────────────┤
│ SORT [목표군 — | 실제 진입 —]   LA [—]  LB [—]  LC [—]    │
│ BOX [Kit ID — | 슬롯 1 — 2 — 3 — 4 — | 편차 —]            │
├ 이력 ─────────────────────────────────────────────────────┤
│ 측정 시각 | 검사 ID | 레인 | attempt | OCV(V) | IR(mΩ)    │
│ 판정 | 사유 | 분류 확인 | Kit/인계             결과 —      │
└───────────────────────────────────────────────────────────┘
```

- 1차 결과와 재검 결과를 시도 번호로 구분하고, 동일 시각의 검사도 검사 ID로 분리한다. RT 사유는 측정 실패·식별 대기·확정 NG·재검 한도 초과를 구분한다. 재검 한도는 기준 출처가 있을 때만 수치로 표시한다.
- OCV와 IR의 미측정은 값 `0`으로 대체하지 않는다. A/B/C 카드는 같은 시각의 목표 특성군과 실제 레인 진입을 구분한다. 버퍼 점유량은 합의된 관측원이 연결된 경우에만 표시한다.
- Kit 슬롯은 서로 다른 Cell ID 4개와 동일 특성군이 확인되어야 `구성 확인`을 표시한다. ID를 선택하면 시도·분류·Kit·인계 이력을 좁힌다. 측정 실패 상태에서 재측정을 강제하거나 레인을 수동 지정하는 조작은 설계 범위 밖이다.

## 3. 설정·알람

```text
┌ 설정·알람   [환경·회차]   [권한]   [브리지/이력 상태]         ┐
├ 판정 기준 ──────────────────┬ 열린 알람 ────────────────────┤
│ 적용 버전 —   PLC 확인 —     │ 심각도 | 스테이션 | 발생 시각  │
│ 이름     현재     제안  단위 │ 코드   | 확인 상태 | 해제 시각 │
│ OCV 하/상한   —     —   mV   │ [알람 확인]      [이력 보기]   │
│ IR 상한       —     —   mΩ   ├ 예외 복구 ────────────────────┤
│ A/B 경계      —     —   mV   │ LOT 상태 —    보류 사유 —     │
│ LOT NG 한도   —     —   건   │ 인계 요청 ID —  수량 대조 —   │
│ RT 한도       —     —   회   │ [보류 해제 요청] [인계 확인]   │
│ [검토] [적용 요청]  미연동   │                  모두 미연동  │
├ 변경 확인: 요청자 — | 사유 — | 명령 ID — | 결과 —            ┤
└──────────────────────────────────────────────────────────────┘
```

- 실제 적용값, 운전자 입력안, 결과 읽기 확인을 나란히 표시한다. 등록된 기준과 실제 PLC 적용값이 다르면 각각의 출처와 버전을 표시한다. 미수집 값을 임시 기본값으로 채우지 않는다.
- 알람의 발행, 작업자 확인, 원인 해제는 별도 상태다. `알람 확인`이 설비 이상을 해제하거나 정지를 재개하지 않는다. 이력 API 장애 시에도 검증된 로컬 알람은 별도로 보인다.
- LOT 해제와 인계 대사에는 대상 ID·상태·권한·사유가 필요하다. 이미 처리된 인계나 수신 시간 초과를 이유로 재배출하는 버튼은 두지 않는다. HMI 조작은 해당 기능의 규약과 권한 검증이 끝날 때까지 비활성화한다.
